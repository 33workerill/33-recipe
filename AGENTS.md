# 33 RECIPE — инструкции для Codex

## Область работы

- Выполняй только явно запрошенный этап Master Plan. Не начинай следующий этап без отдельного задания.
- На Phase 01 разрешены только техническая основа, документация и временный стартовый экран. Не добавляй Recipe Model, редактор, хранение, экспорт или AI Studio.
- Не меняй несвязанные файлы и не удаляй чужую работу. Перед правками проверяй состояние Git и существующие инструкции.

## Архитектура и код

- Используй React, TypeScript strict, Vite, Tailwind CSS и npm. Разделяй ответственность по небольшим компонентам; не вводи абстракции заранее.
- В будущих этапах Recipe Data, Layout, Theme и Export должны иметь независимые границы. Не представляй планируемые модули как существующие.
- Используй алиас `@/` для файлов из `src/`. Пиши семантическую, доступную разметку и адаптивные стили. Не добавляй фиктивные действия.
- Следуй ESLint и Prettier. Избегай `any`, не скрывай ошибки TypeScript и не храни секреты в коде.

## Навыки

Если доступны пользовательские 33 CODEX SKILLS, применяй по задаче: Premium UI/UX для интерфейса, Frontend Engineer для React/Vite, Senior Code Engineer для архитектуры, QA & Testing для проверки, Smart Debugger для воспроизведённых ошибок, Safe Refactor для узких рефакторингов, Context/Token Saver для экономного чтения. Не выдумывай отсутствующие навыки и не устанавливай их без необходимости.

## Git, PR и проверки

- Работай в отдельной ветке; PR направляй в `main`. Не сливай PR без одобрения владельца.
- Перед PR выполни `npm ci`, `npm run lint`, `npm run typecheck`, `npm run format:check`, `npm run test:run`, `npm run build`.
- В итоговом отчёте укажи выполненное, фактические результаты проверок, ссылки на GitHub/Vercel и ограничения. Не утверждай успех без проверки.
