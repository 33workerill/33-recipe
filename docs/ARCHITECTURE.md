# Архитектура

## Реализовано

```text
src/
  App.tsx                         навигация и подключение рабочего состояния рецептов
  Root.tsx                        выбор между / и /ui без маршрутизатора
  components/shell/
    AppSidebar.tsx                desktop sidebar, мобильный Sheet и выбор темы
    EditorWorkspace.tsx           рабочий редактор рецепта и статусы сохранения
    IngredientEditor.tsx          группы и ингредиенты
    StepEditor.tsx                шаги приготовления
    NumericField.tsx              безопасный промежуточный числовой ввод
    PreviewPanel.tsx              навигация листов, масштаб и live preview
    PresentationSettings.tsx      секция 06 в редакторе
    ImageManager.tsx               обложка и галерея фотографий
    WorkspacePage.tsx             библиотека, недавние, настройки и backup
    navigation.ts                 разделы оболочки
  components/ui/                  примитивы shadcn/ui (Radix)
  features/recipes/model/         независимые типы, схемы, фабрики и проверки рецепта
  features/recipes/data/          IndexedDB, ревизии, автосохранение и backup
  features/recipes/presentation/  независимые стили, форматы и настройки предпросмотра
  pages/UiShowcase.tsx            демонстрация Design System
  theme/                          light / dark / system, хранение, системные изменения
  styles/index.css                семантические токены, типографика и motion
  test/setup.ts                   окружение Vitest / Testing Library
index.html                        раннее применение темы до загрузки React
vercel.json                       rewrite прямого запроса /ui на index.html
```

`Root` выбирает страницу по `window.location.pathname`. Главный маршрут `/` сразу показывает рабочее пространство; `/ui` загружается отдельным чанком. Для этих двух маршрутов библиотека маршрутизации не нужна.

На широких экранах отображаются sidebar, центральная область и предпросмотр. До ширины `xl` редактор и предпросмотр переключаются локальным UI-состоянием. На мобильных устройствах sidebar открывается через Sheet. Навигация между редактором, коллекцией, недавними и настройками хранится в памяти React. Библиотека читает реальные рецепты из IndexedDB; недавние хранят только список ID в localStorage. Предпросмотр строится из несохранённого React state, поэтому отражает ввод до автосохранения.

Секции редактора используют Accordion из Design System. Presentation-конфигурация хранится отдельно от Recipe Model в localStorage, выбранное состояние передаётся редактору и preview из App. `presentation/layout.ts` задаёт геометрию в миллиметрах и детерминированный план страниц; DOM ResizeObserver панели предпросмотра сверяет фактическую высоту видимого листа и при переполнении уменьшает лимит упаковки, создавая дополнительные листы. Текст не скрывается. A4/A5 Duplex отображает фронт/бек одной и той же геометрии листа и дополнительные парные листы. Масштабирование применяется к экранной рамке и не меняет геометрию листа. Ограничения остаются: измеряется только текущая сторона/лист; если отдельный атомарный блок сам выше доступной области, UI предупреждает, но точное размещение такого блока и вывод в файлы относятся к экспортному этапу.

Настройки предпросмотра сохраняются в versioned localStorage ключе на ID рецепта. Пользовательские пресеты хранят только небольшие конфигурации под отдельным versioned ключом и не дублируют рецепт. App Theme не меняет цвета и типографику печатной поверхности. Экспорт, печатная пагинация, двусторонний вывод на принтер и книжная раскладка A4 → A5 остаются отключёнными до Phase 08.

Тема интерфейса задаётся классом `.dark` на `html` и семантическими CSS-переменными. Выбор `light | dark | system` хранится под ключом `33-recipe-app-theme`; скрипт в `index.html` применяет класс до загрузки React.

Phase 04 добавляет модель рецепта без связи с React. `schemas.ts` содержит строгие Zod-схемы версии 1, `types.ts` выводит из них типы, `factories.ts` создаёт сущности с UUID и UTC-датой, `validation.ts` отдельно проверяет корректность черновика и полноту готового рецепта. `serialization.ts` выполняет проверяемый JSON round-trip, а `versioning.ts` отклоняет неподдерживаемые версии. Тестовые рецепты находятся только в fixtures модели и не подключаются к интерфейсу. Подробности — в [RECIPE_MODEL.md](RECIPE_MODEL.md).

Phase 05 Fast Track добавляет отдельный слой данных в `features/recipes/data/`. Репозиторий сохраняет валидированный JSON в IndexedDB и использует ревизии для защиты от устаревшей записи из другой вкладки. Phase 06 обновляет базу с версии 1 до 2, не удаляя хранилище рецептов, и добавляет store `images` для Blob. Ключи изображений совпадают с `MediaAsset.id`, записи имеют `recipeId`; операции записи/замены/удаления и metadata выполняются одной транзакцией. При дублировании рецепта Blob копируются отдельно. JSON backup содержит только модель и метаданные; фотографии в него не входят. Подробности — в [EDITOR_LIBRARY.md](EDITOR_LIBRARY.md) и [IMAGES_AND_PREVIEW.md](IMAGES_AND_PREVIEW.md).

## Границы проекта

Статический клиент не имеет сервера, аккаунтов, облачной синхронизации и фоновых заданий. Recipe Model остаётся независимой от IndexedDB, UI и presentation-конфигурации. Превью поддерживает стили и геометрию форматов; генерация файлов и точная печатная пагинация остаются отдельными этапами. App Theme управляет только интерфейсом и не определяет оформление рецепта. Поддерживаются JPEG, PNG и WebP; HEIC/HEIF без браузерного декодирования сообщается как неподдерживаемый формат. JSON backup не включает Blob.
