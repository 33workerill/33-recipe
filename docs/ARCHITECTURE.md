# Архитектура

## Реализовано

```text
src/
  App.tsx                    стартовая страница Phase 01 на семантических токенах
  Root.tsx                   выбор между / и /ui без маршрутизатора
  main.tsx                   точка входа React
  components/ui/             примитивы shadcn/ui (Radix)
  pages/UiShowcase.tsx       композиция и интерактивные примеры Phase 02
  theme/theme-context.ts     контракт темы и хук
  theme/theme-provider.tsx   light / dark / system, хранение, системные изменения
  theme/theme-toggle.tsx     доступный переключатель
  styles/index.css           семантические токены, типографика, motion
  test/setup.ts              окружение Vitest / Testing Library
index.html                   раннее применение темы до загрузки React
vercel.json                  rewrite прямого запроса /ui на index.html
components.json              конфигурация shadcn/ui
```

`Root` выбирает страницу по `window.location.pathname`. Для одного служебного маршрута библиотека маршрутизации не нужна. Vercel перенаправляет только запрос `/ui` к HTML приложения; остальные статические ресурсы обслуживаются как обычно.

Тема приложения задаётся классом `.dark` на `html` и семантическими CSS-переменными. Выбор `light | dark | system` хранится под ключом `33-recipe-app-theme`. Небольшой скрипт в `index.html` устанавливает класс до загрузки CSS, Theme Provider отслеживает дальнейшие изменения и системную тему.

Примитивы в `src/components/ui/` созданы официальным shadcn CLI. Изменения размеров кнопки, поля и выбора учитывают использование на сенсорном экране. Страница Showcase компонует их и хранит только демонстрационное состояние.

## Границы проекта

Статический клиент не имеет API, базы данных, авторизации и фоновых заданий. Phase 02 не создаёт структуру рецепта и редактор. Будущие **Recipe Data**, **Layout**, **Recipe Theme** и **Export** получат отдельные границы. Тема приложения управляет только интерфейсом и не должна автоматически менять будущую печатную форму рецепта.
