# Архитектура

## Реализовано

```text
src/
  App.tsx                         навигация и подключение рабочего состояния рецептов
  Root.tsx                        выбор между / и /ui без маршрутизатора
  components/shell/
    AppSidebar.tsx                desktop sidebar, мобильный Sheet и выбор темы
    EditorWorkspace.tsx           рабочий редактор рецепта и статусы сохранения
    IngredientEditor.tsx          группы и ингредиенты
    StepEditor.tsx                шаги приготовления
    NumericField.tsx              безопасный промежуточный числовой ввод
    PreviewPanel.tsx              нейтральная пустая область предпросмотра
    WorkspacePage.tsx             библиотека, недавние, настройки и backup
    navigation.ts                 разделы оболочки
  components/ui/                  примитивы shadcn/ui (Radix)
  features/recipes/model/         независимые типы, схемы, фабрики и проверки рецепта
  features/recipes/data/          IndexedDB, ревизии, автосохранение и backup
  pages/UiShowcase.tsx            демонстрация Design System
  theme/                          light / dark / system, хранение, системные изменения
  styles/index.css                семантические токены, типографика и motion
  test/setup.ts                   окружение Vitest / Testing Library
index.html                        раннее применение темы до загрузки React
vercel.json                       rewrite прямого запроса /ui на index.html
```

`Root` выбирает страницу по `window.location.pathname`. Главный маршрут `/` сразу показывает рабочее пространство; `/ui` загружается отдельным чанком. Для этих двух маршрутов библиотека маршрутизации не нужна.

На широких экранах отображаются sidebar, центральная область и предпросмотр. До ширины `xl` редактор и предпросмотр переключаются локальным UI-состоянием. На мобильных устройствах sidebar открывается через Sheet. Навигация между редактором, коллекцией, недавними и настройками хранится в памяти React. Библиотека читает реальные рецепты из IndexedDB; недавние хранят только список ID в localStorage. Пустые состояния не содержат фиктивных рецептов.

Секции редактора используют Accordion из Design System. Создание, изменение и сохранение рецептов работают; предпросмотр и экспорт оформленного рецепта пока недоступны. Бумажная поверхность в пустом предпросмотре имеет отдельные нейтральные CSS-переменные и сохраняет один вид при смене темы приложения; это ещё не макет печатного рецепта.

Тема интерфейса задаётся классом `.dark` на `html` и семантическими CSS-переменными. Выбор `light | dark | system` хранится под ключом `33-recipe-app-theme`; скрипт в `index.html` применяет класс до загрузки React.

Phase 04 добавляет модель рецепта без связи с React. `schemas.ts` содержит строгие Zod-схемы версии 1, `types.ts` выводит из них типы, `factories.ts` создаёт сущности с UUID и UTC-датой, `validation.ts` отдельно проверяет корректность черновика и полноту готового рецепта. `serialization.ts` выполняет проверяемый JSON round-trip, а `versioning.ts` отклоняет неподдерживаемые версии. Тестовые рецепты находятся только в fixtures модели и не подключаются к интерфейсу. Подробности — в [RECIPE_MODEL.md](RECIPE_MODEL.md).

Phase 05 Fast Track добавляет отдельный слой данных в `features/recipes/data/`. Репозиторий сохраняет валидированный JSON в одной IndexedDB-базе и использует ревизии для защиты от устаревшей записи из другой вкладки. Рабочий hook последовательно завершает отложенные записи перед переходом, а статус «Сохранено» появляется только после завершения транзакции. Backup импортируется атомарно и отклоняет конфликтующие ID. Подробности — в [EDITOR_LIBRARY.md](EDITOR_LIBRARY.md).

## Границы проекта

Статический клиент не имеет сервера, аккаунтов, облачной синхронизации и фоновых заданий. Recipe Model остаётся независимой от IndexedDB и UI. Будущие **Layout**, **Recipe Theme** и **Export** получат отдельные границы. App Theme управляет только интерфейсом и не определяет оформление будущих печатных рецептов. Медиа пока представлены только метаданными в модели; загрузки файлов нет.
